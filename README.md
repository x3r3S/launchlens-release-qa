# LaunchLens

LaunchLens is a compact release-QA workspace for a storefront team that needs a decision, not a vague list of observations. It turns five deliberately seeded defects into reproducible findings and runs the same checks against a corrected build.

![LaunchLens release evidence workspace](screenshots/launchlens-qa-wide.png)

## The workflow

1. Review build `1.4.2` at a simulated viewport.
2. Open a finding with severity, reproduction steps, expected behaviour, actual behaviour and evidence.
3. Switch to build `1.4.3` and run a like-for-like retest.
4. Export the resulting evidence as JSON.

The default mobile run produces a score of **51/100** with five open findings. The fixed-build retest resolves the same five checks and produces **100/100**. Those values are generated by the domain model and cross-checked against the written evidence during `npm run verify`.

## Run locally

Requirements: Node.js 20 or newer. There are no runtime dependencies.

```bash
npm run demo
```

Open `http://127.0.0.1:4173/`.

Run the complete verification gate:

```bash
npm run verify
```

That command checks JavaScript syntax, runs the ten domain tests and verifies that the evidence files still match the current model.

## Project boundary

This is a self-initiated portfolio case using an invented storefront and deliberately seeded defects. The viewport matrix is deterministic browser-size simulation; it is not evidence of Safari, iOS, Android or physical-device coverage. The app makes no external requests and writes only the report file the reviewer explicitly exports.
